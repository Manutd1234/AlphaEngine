# Optional: the cross-encoder re-ranker for research retrieval.
#
#   pip install -r requirements-rerank.txt
#
# Deliberately NOT part of requirements-core.txt. The desk retrieves, fuses by
# RRF and grades with no re-ranker at all, and every test in the suite passes
# without a byte of this installed — modules/research_rerank.py reports
# fastembed's absence exactly the way it reports an unset RERANK_MODEL_PATH, and
# hands back the fused order untouched and truncated. Installing this buys
# precision; it is never a prerequisite for an answer.
#
# fastembed rather than a hosted re-ranker, and the reason is the one that keeps
# the Anthropic SDK out of requirements-recall.txt: this is ONNX on the CPU. No
# API key on the retrieval path, no vendor outage that becomes a retrieval
# outage, no query text and no desk research leaving the box, and no accuracy
# that changes silently when somebody else ships a model version. Cohere Rerank
# and Voyage are both better scorers and were rejected on exactly that.
#
# Two things it needs beyond the package:
#
#   RERANK_MODEL_PATH   the directory fastembed resolves BAAI/bge-reranker-base
#                       from. Empty by default, which is a reported state and
#                       not a fault.
#   a seeded directory  the ONNX weights are fetched once into that path. Do it
#                       at image build time, never on the request path: the
#                       first query after boot would otherwise pay for a
#                       download, and CI is network-free by construction.
#
# THAT SEEDING NOW HAS A COMMAND, and until it did, this file prescribed a build
# step that nothing in the tree performed — which is how the re-ranker reached
# production as a code path with no weights behind it and no test that had ever
# executed it:
#
#   python tools/bench_rerank.py --seed --model-path /models/bge-reranker-base
#
# The same call is what CI's opt-in `rerank-real` job makes, so the image build
# and the job seed through one code path rather than two that can disagree about
# where the weights go. What it costs, measured cold: 5 files, 21.7 s, 1.05 GiB
# on disk (`--seed` prints it) — one blob of 1,112,459,588 bytes of fp32 ONNX,
# which is the whole
# argument for caching it in CI and for never putting it on a request path.
#
# WHAT THE MODEL COSTS PER QUERY is measured now too, by the same tool, and the
# figure it replaced was out by up to 19x. Twenty pairs — the width
# `research_rerank.RERANK_CANDIDATES` widens to — took 197 ms of wall clock on
# short rows and 1,523 ms at the 2,000-character truncation ceiling, burning
# 1.8 s and 12.6 s of CPU respectively across ~9 of an 18-core box. Load off a
# seeded directory: 0.45 s, once per process. Run `tools/bench_rerank.py` on the
# box you intend to deploy on before believing any of those numbers there:
# onnxruntime sizes its thread pool from the cores it finds, so every one of
# them is a property of the machine that took it.
#
# Pinned to a line rather than floated, for the reason scikit-learn is: a
# re-ranker that scores differently between releases re-orders what the desk was
# shown, and the order IS the research result.
#
# onnxruntime is fastembed's own dependency and is named here anyway so the CPU
# distribution is the one on record. `onnxruntime-gpu` is a DIFFERENT package,
# not a flag, and substituting it wants a CUDA runtime this VM does not have.
fastembed>=0.4,<0.8
onnxruntime>=1.17
